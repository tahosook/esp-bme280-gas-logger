# リリース計画

GAS Web Appの本番リリースと旧システム廃止までの手順を整理する。

---

## 前提

- 旧システムは停止済みで、並行稼働は行わない。
- 本番デプロイと旧廃止は人間の承認後に実施する。
- デプロイ手順は `docs/deployment.md` の本番デプロイ手順と整合させる。

---

## 本番デプロイ手順

1. スプレッドシートを作成し、DATAシートの先頭行を用意する。
2. タイムゾーンを`Asia/Tokyo`に設定する。
3. GASプロジェクトを作成し、`gas/Code.gs`を反映する。
4. Script Propertiesに必要なキーを設定する。
5. `/dev` のテストデプロイで事前確認する。
6. 本番は既存の `/exec` デプロイを更新し、URLを維持する。
7. 更新前後で `/exec` URL が同一であることを確認する。
8. Webhook/LINE/トリガーを設定する。
9. 正常系・異常系のスモークテストを実施する。
10. スモークテスト結果を秘密情報なしで `docs/test-results/` に記録する。

---

## ロールバック方針

| 観点 | 方針 |
| --- | --- |
| 切り替え | 旧システムは停止済みのため、並行稼働によるロールバックは行わない |
| 復旧 | 問題発生時は新システム内で修正し、デプロイを戻してから再適用する |

---

## ロールバック手順

1. 直前の正常バージョンが分かる状態で、**デプロイを管理**から以前のバージョンへ戻す。
2. 更新前の `/exec` URL でcurlなどを用いて動作を確認する。
3. 原因調査と修正を実施する。
4. 再デプロイ前に `/dev` で検証し、再度本番反映する。

---

## 旧システム廃止条件

- 新システムが最低1週間安定して動作している
- データ欠損/重複が許容範囲内である
- 通知/監視が安定している
- 人間による旧廃止承認が得られている

---

## 人間による承認が必要なタイミング

- スプレッドシート構成の最終決定
- Script Propertiesのキー/値の決定
- 本番Web Appデプロイ
- LINE/Webhook設定の変更
- 本番切り替え
- 旧システム廃止
