# LINE Bot UI / UX 仕様

## 1. 概要
ESP8266 + BME280 のセンサーログを活用した LINE Bot の応答やアラート通知を、テキスト主体から視覚的な「Flex Message」に刷新し、スヌーズ状態・停止期限の可視化および24時間の温湿度推移グラフ画像（QuickChart）の自動返信機能を提供します。

## 2. コマンド体系とエイリアス一覧

リッチメニューの英語表記化および従来の日本語入力の両方を完全サポートします（大文字・小文字、全角・半角、前後の空白は自動正規化されます）。

| コマンド | 許容エイリアス（正規化後） | アクション |
| :--- | :--- | :--- |
| **NOW** | `now`, `状況`, `状態`, `現在`, `status` | 最新ステータスカード（Flex Message）を返信。スヌーズ中であれば停止期限を可視化 |
| **SNOOZE** | `snooze`, `スキップ`, `おやすみ`, `skip` | 翌朝 08:00 JST までアラート停止＆完了カード（最新温湿度付き）を返信 |
| **TRENDS** | `trends`, `グラフ`, `24h`, `推移` | QuickChart による直近24h温湿度推移グラフ画像を返信 |
| **CLEAR** | `clear`, `クリア`, `解除` | スヌーズ解除＆監視状態をリセットし、監視再開メッセージを返信 |

## 3. Flex Message のレイアウト仕様

### 3.1 NOW（状況）コマンドの応答
現在のスヌーズ有効フラグおよび期限（`PropertiesService` の `MONITOR_SKIP_UNTIL`）を判定し、動的にカードレイアウトを切り替えます。

- **スヌーズ中（有効期限前）の場合**:
  - **ヘッダー**: 🔕 **SNOOZE中**（オレンジ系 `#e67e22`）
  - **サブテキスト**: `停止期限: MM/dd 08:00 まで (翌朝自動再開)`
  - **フッターボタン**: `[ 🔔 監視を再開（CLEAR） ]`（アクション text: `"CLEAR"`）
- **通常監視中（Active）の場合**:
  - **ヘッダー**: 🔔 **監視中（Active）**（グリーン系 `#27ae60`）
  - **フッターボタン**: `[ 🔕 翌朝までSNOOZE ]`（text: `"SNOOZE"`）と `[ 📈 TRENDS (24h) ]`（text: `"TRENDS"`）
- **共通データ表示部**:
  - 気温 (℃) [正常 / 🚨 超過]
  - 湿度 (%) [正常 / 🚨 超過]
  - 気圧 (hPa)
  - 不快指数 (DI) ＋ 色付きのステータスバッジ（肌寒い `#3498db` / 快適 `#27ae60` / やや暑い `#e67e22` / 暑くてたまらない `#e74c3c`）
  - 容積絶対湿度 ($g/m^3$)
  - 最終受信日時（JST）

### 3.2 SNOOZE（おやすみ）コマンドの応答
「翌朝 08:00 JST までアラート停止」を反映した完了カードを返信します。
- **ヘッダー**: 🔕 **SNOOZE設定完了**（`#e67e22`）
- **強調表示**: `停止期限: MM/dd 08:00 まで停止`（翌朝自動再開の注記）
- **現在値表示**: 設定時点の最新室温・湿度
- **フッターボタン**: `[ 🔔 監視を再開（CLEAR） ]`（アクション text: `"CLEAR"`）

### 3.3 アラートプッシュ通知
監視閾値を超過した際のプッシュ通知カードです。
- **ヘッダー**: ⚠️ **監視アラート**（`#e74c3c`）
- **本文**: 超過した数値と判定内容
- **フッターボタン**: `[ 🔕 翌朝8時までSNOOZE ]`（アクション text: `"SNOOZE"`）

## 4. リッチメニューの推奨配置
操作性を高めるため、LINE Official Account Manager 等で以下の 3 枠リッチメニューの配置を推奨します。

- **左枠**: `[🔕 SNOOZE]` (アクション: テキスト「SNOOZE」を送信)
- **中央枠**: `[🌡️ NOW]` (アクション: テキスト「NOW」を送信)
- **右枠**: `[📈 TRENDS]` (アクション: テキスト「TRENDS」を送信)

## 5. 直近24hグラフ画像生成機能（TRENDS）
コマンド「TRENDS」「グラフ」「24h」「推移」を受信すると、直近の24時間分（5分間隔で最大288件）のデータをもとに折れ線グラフを生成し、LINEへ画像として返信します。

- **グラフ生成エンジン**: [QuickChart API](https://quickchart.io/)（GET URL ダイレクト参照方式）
- **データ取得元**: 現在アクティブな Google スプレッドシート（`DATA` または `2026` 等のシート）の末尾から直近最大 288 行を取得
- **グラフの仕様**:
  - X軸: 時刻 (`HH:mm`)
  - Y軸 (左 `yTemp`): 温度 (℃) / 赤色 (`#ef4444`)
  - Y軸 (右 `yHum`): 湿度 (%) / 青色 (`#3b82f6`)
  - 解像度・サイズ: 幅 600 × 高さ 360 (devicePixelRatio: 2.0)
- **LINE 2,000 文字制限対策（URL 圧縮仕様）**:
  - LINE Messaging API の `image` メッセージ（`originalContentUrl`）には最大 2,000 文字の長さ制限があります。
  - 288 件を約 30 点（約 45 分間隔）にサンプリング（間引き）。
  - X 軸ラベルは 3 時間おき（および先頭・末尾）にのみ表示し、中間 tick のラベルを空文字 `""` にして URL 長を圧縮。
  - 数値は小数点第 1 位（`toFixed(1)`）に丸め。
  - 万が一 2,000 文字を超える場合は自動的にサンプリング間隔を広げるフェイルセーフを内蔵。
- **フォールバック処理**:
  - データ行が存在しない（0件またはヘッダーのみ）場合:
    「グラフを生成するためのデータが不足しています。」とテキストメッセージで返信。

## 6. エラーハンドリングと手動デバッグ機能
- **Webhook エラーハンドリング**:
  - 予期せぬ例外発生時は `console.error` および `ErrorLog.gs` にスタックトレースを記録し、LINE トーク画面へ「⚠️ GAS処理エラー: {エラー詳細}」をフォールバック返信。
- **手動デバッグ関数 (`DebugTest.gs`)**:
  - `debugTest_buildQuickChartUrl()`: GAS エディタからワンクリックで QuickChart URL の生成と URL 文字長（2,000文字以内か）を検証。
  - `debugTest_handleLineWebhook_Trends()`: LINE への実送信を行わずに Webhook 応答オブジェクトの構造を検証。
