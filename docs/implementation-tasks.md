# 実装タスク一覧

CLINE Freeモデルで1回ずつ依頼できる粒度に分解する。
1タスク = 1コミットを基本とする。

---

## Task 01: GASプロジェクト構成整理
- 目的: `gas/` とドキュメントの役割を明確にし、実装開始時の混乱をなくす
- 変更対象: `gas/Code.gs`、`gas/README.md`
- 実装内容: 既存コードの整理と補足README更新
- テスト: ファイル一覧/役割のレビュー
- 完了条件: 実装者が`gas/`の責務を一読で理解できる
- 注意点: 仕様変更ではなく、理解しやすさの整理に留める

---

## Task 02: Script Properties整理
- 目的: 必要な設定キーと運用ルールを確定する
- 変更対象: `gas/Code.gs`、`docs/deployment.md`
- 実装内容: キー一覧の整理、取得/設定ヘルパーの整備
- テスト: キー一覧のレビュー、欠損時のエラー確認
- 完了条件: 設定キーが一覧化され、誤設定時の挙動が明確になっている
- 注意点: 実値をドキュメントに記載しない

---

## Task 03: DATAシート定義
- 目的: 生データ保存用シートの列/書式/保持方式を確定する
- 変更対象: `docs/architecture.md`、`docs/deployment.md`
- 実装内容: 列定義、日時書式、保持期間方針の文書化
- テスト: 設計レビュー
- 完了条件: DATAシートの仕様が文書化されている
- 注意点: 要判断項目は人間承認を条件に凍結する

---

## Task 04: POST API実装
- 目的: 最小構成でESP8266からのPOSTをDATAに保存する
- 変更対象: `gas/Code.gs`
- 実装内容: `doPost`のJSON解析、トークン検証、行追記、成功応答
- テスト: 正常POSTで1行追加されること、タイムゾーンが`Asia/Tokyo`であること
- 完了条件: 最小保存が動く状態になっている
- 注意点: バリデーションは次のタスクに分離してよい

---

## Task 05: POSTバリデーション実装
- 目的: 不正データを適切に拒否する
- 変更対象: `gas/Code.gs`
- 実装内容: `api_version`/`token`/測定値の型/範囲チェック、エラー応答統一
- テスト: 欠損/型不正/範囲外/境界値の確認
- 完了条件: 異常系が設計通りに拒否される
- 注意点: 旧システムの固定行数チェックは持ち込まない

---

## Task 06: 重複/欠損データ方針確定
- 目的: 重複送信や欠損への運用ルールを明確にする
- 変更対象: `docs/test-plan.md`
- 実装内容: 重複排除は行わず受信順に記録する方針、欠損許容/復旧方針の文書化
- テスト: 方針レビュー
- 完了条件: 運用者が例外時の挙動を理解できる
- 注意点: 永続キューは要件外のため実装しない

---

## Task 07: 日次集計実装
- 目的: DATAから1日分を集計する
- 変更対象: `gas/Code.gs`、`docs/deployment.md`
- 実装内容: 日別シート作成または更新、Average/Min/Max算出
- テスト: 実データを用いた集計結果確認
- 完了条件: 日次集計が正しく生成される
- 注意点: 生DATAを編集しないこと

---

## Task 08: TOTAL/グラフ実装
- 目的: 複数日の要約と可視化を作成する
- 変更対象: `gas/Code.gs`
- 実装内容: TOTAL更新、グラフ生成/更新ロジック
- テスト: TOTALの整合性、グラフの内容確認
- 完了条件: TOTAL/グラフが期待通りになる
- 注意点: グラフは必要最小限に留める

---

## Task 09: 監視基盤実装
- 目的: 温度/湿度/暑さ指数相当の監視条件を実装する
- 変更対象: `gas/Code.gs`
- 実装内容: 閾値取得、状態判定、通知条件の実装
- テスト: 条件超過時に通知が走ること
- 完了条件: 監視条件が動作する
- 注意点: 名称/計算式は要判断項目のため承認後に確定する

---

## Task 10: 通知抑制実装
- 目的: 超過継続中の重複通知を抑制する
- 変更対象: `gas/Code.gs`
- 実装内容: 状態管理：正常/超過/抑制/復帰、Script Propertiesによる状態保持
- テスト: 継続超過で再通知しないこと、復帰後に再通知されること
- 完了条件: 通知の重複が抑制される
- 注意点: 旧システムの振る舞いを参考にしつつ、新設計で実装する

---

## Task 11: LINE Bot実装
- 目的: 状況/スキップ/クリアをLINEから操作する
- 変更対象: `gas/Code.gs`、`docs/deployment.md`
- 実装内容: Webhook受付、コマンド分岐、応答生成、状態更新
- テスト: 各コマンドの応答確認
- 完了条件: LINE上で操作が完結する
- 注意点: Webhook/LINEチャネル設定は人間確認が前提

---

## Task 12: エラー処理/ログ強化
- 目的: 障害調査を容易にする
- 変更対象: `gas/Code.gs`
- 実装内容: try/catchの整理、エラー種別の分離、ログ出力設計
- テスト: 異常系のログ確認
- 完了条件: 主要障害で原因が追える
- 注意点: 秘密情報をログへ出力しない

---

## Task 13: 結合テスト/検証記録整備
- 目的: 全機能の連携を確認し、結果を残す
- 変更対象: `docs/test-results/*`、`docs/test-plan.md`
- 実装内容: 手順書の整備、結果テンプレート作成
- テスト: テスト手順のdry run
- 完了条件: 検証手順が再現可能になっている
- 注意点: トークン等は記載しない

---

- 目的: 本番運用に必要な手順を明確にする
- 変更対象: `README.md`、`docs/deployment.md`
- 実装内容: デプロイ手順、ロールバック手順の追記
- テスト: 手順レビュー
- 完了条件: 作業者が手順通りに進められる
